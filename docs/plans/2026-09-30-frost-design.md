# Frost — Design Document

Date: 2026-09-30

Frost is a macOS menu bar manager (similar to [Ice](https://github.com/jordanbaird/Ice)) that hides some menu bar
items and can show the hidden items in a panel that drops down below the menu bar.

## Goals and constraints

- Minimum system: **macOS 26 (Tahoe)**, no compatibility with older versions; Liquid Glass design language
  throughout.
- A good-looking, modern GUI.
- Direct distribution (not the App Store, not sandboxed). For now a local self-signed certificate keeps the signing
  identity stable; it can be replaced with Developer ID later.
- Toolchain: Xcode 27 / Swift 6.4, project generated by XcodeGen, Swift 6 strict concurrency.

## v1 scope

1. **Sections**: Visible / Hidden / Always Hidden; clicking the Frost item toggles the Hidden section, ⌥-click also
   shows the Always Hidden section; automatic rehide.
2. **Frost Bar**: a glass panel that drops down below the menu bar, shows the hidden items, and clicking one triggers
   the original item.
3. **Visual drag-and-drop arrangement**: the settings window shows every item as an image; drag items between
   sections.

Not in v1: global hotkeys, hover/scroll triggers, menu bar styling, item search.

## Approach: separator push-out (same as Ice)

Frost owns three `NSStatusItem`s (left → right: Always Hidden separator, Hidden separator, Frost item):
- **Frost item**: left edge of the Visible section; never grows.
- **Hidden separator**: right next to the Frost item, on its left; the boundary between the Hidden and Visible
  sections.
- **Always Hidden separator**: the boundary between the Hidden and Always Hidden sections.

Hide = set the separator's `length` to ~10000, pushing the items on its left off screen; show = restore it. Basic
hiding/showing needs no permissions at all.

Rejected approaches: an overlay window (doesn't free up space, and the notch problem has no solution); pure
Accessibility AXPress (menus of hidden items would pop up off screen; kept only as a fallback).

**Main risk**: on macOS 26 the ownership of menu bar item windows changed (Ice has identification problems on
Tahoe). The first implementation step is a half-day spike on a real Mac to verify enumerating items, moving them with
⌘-drag and capturing item images.

## Architecture

### FrostCore (standalone Swift package, unit-testable)

- `MenuBarItemScanner`: enumerates status-bar-level windows (`CGWindowList`, private CGS API if needed) and produces
  `MenuBarItem`s (pid, bundle ID, frame, windowID); rescans when apps launch or quit.
- `SectionModel`: decides an item's section from its x coordinate and the positions of the two separators (pure
  function).
- `ItemMover`: turns "move A after B" into a ⌘-drag `CGEvent` sequence, verifies after moving and retries. Needs the
  Accessibility permission.
- `ItemImageCapturer`: captures item images with ScreenCaptureKit and caches them. Needs the Screen Recording
  permission.

### App layer

- `SectionController`: manages the two separator `NSStatusItem`s, showing/hiding and automatic rehide.
- `FrostBarPanel`: a non-activating `NSPanel` with a Liquid Glass background. Clicking an item → temporarily move it
  into the Visible section → simulate a click → move it back after the menu closes.
- `SettingsWindow`: layout editor + Behavior + About.
- `Onboarding`: permission onboarding on first launch.

## UI

- **Menu bar**: the Frost item is a snowflake SF Symbol; left-click toggles (spring animation), ⌥-left-click
  includes the Always Hidden section, right-click opens a small menu (Settings / Quit). The Always Hidden separator
  is a thin vertical line, visible only while the layout editor is open.
- **Display mode**: settings offer expanding "In Menu Bar" or the "Frost Bar"; notched displays default to the
  Frost Bar.
- **Frost Bar**: a capsule-shaped glass panel (`.glassEffect()`) below the Frost item (or the notch); items at their
  original size in one row, with hover highlight + the app name; fades out with a slight scale; closes on an outside
  click or Esc.
- **Settings window**: transparent title bar + glass background, about 640×520, a segmented control at the top:
  - Layout: three glass section bands with live item images; items can be dragged across sections and reordered.
    After a drop the item shows as pending until the real menu bar move succeeds.
  - Behavior: auto-rehide delay, display mode, launch at login (`SMAppService`).
  - About: version, permission status.
- **Onboarding**: two glass cards (Accessibility, Screen Recording); the grant button opens the matching System
  Settings pane, and the status is polled and checked off automatically.

## Error handling

- Missing/revoked permissions: the Frost Bar and the layout editor show a "permission needed" placeholder that links
  back to onboarding; hiding/showing keeps working.
- Failed move: retry at most twice; if it still fails, show a toast in the editor.
- No items found: say so explicitly instead of failing silently.
- Frost Bar click forwarding: if no menu/popup is detected within 1 second after the click, move the item back
  immediately; while a menu is open, wait for it to close before moving back (no limit for menus — a menu always
  closes when the user clicks elsewhere; popovers / panels at most 60 seconds); if the anchor disappears, fall back
  to the original section boundary.

## Testing

- `FrostCore` unit tests: section classification, layout diff → move plan, filtering of scan results (pure functions
  driven by fixture data).
- Spike verification scripts: on day 0, verify enumeration / moving / capturing on a real Mac.
- Manual checklist: notched vs. non-notched displays, multiple displays, Light/Dark Mode, revoked permissions.
